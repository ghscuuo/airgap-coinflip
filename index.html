    Defensive Rationale & Philosophy

    1. Why build another generator?

    While Ian Coleman's generator is the gold standard for derivation, it is a "kitchen sink" tool that accepts many inputs. This tool is a hyper-focused Entropy Ingestion Engine. It forces a single, mathematically pure path to generating a wallet: 128 physical coin flips.

    2. The "Hard Block" on Human Entropy

    Humans cannot generate random numbers. If you type random 1s and 0s on a keyboard, behavioral sweep bots will crack your seed and drain your funds. We run aggressive statistical tests on your flips. If we detect human patterns (repeating blocks, extreme bias), the engine physically halts and refuses to generate keys. No security theater.

    3. Extreme Memory Hygiene

    Browser garbage collection (GC) is unpredictable. If cryptographic buffers are orphaned, they linger in RAM. We implemented manual derivation paths and aggressive .fill(0) wipes for all intermediate nodes, chain codes, and master seeds before they ever reach the GC.

    4. UI Segregation (The Red Border)

    Public data (Descriptors, XPUBs) and Private data (Seeds, XPRVs) are strictly segregated. Private material is hidden in a red-tinted tab to prevent accidental screen-sharing leaks or confusion when moving data via QR code to an online watch-only wallet like Sparrow.

    5. The Hermetic Seal

    The Content Security Policy absolutely forbids all external network I/O. The HTML is a 100% self-contained artifact built with a deterministic timestamp (SOURCE_DATE_EPOCH) so anyone can compile the source and verify they get the exact same byte-for-byte SHA-256 hash.
